# 04｜カスタマイズ手順（決めた内容をどこに書くか）

02 で決めた内容を、実際のファイルに反映する手順です。

---

## ■ 全体の仕組み

このシステムは**プロファイル差し替え式**です。
`config.yaml` の中に複数の設定が入っていて、`active_profile` で切り替えます。

```
config.yaml
 ├ active_profile: tsubaki      ← 今どれを使うか
 └ profiles:
     ├ tsubaki       （占い・恋愛）
     ├ local_owner   （店舗オーナー向け集客）
     └ ai_sidehustle （副業向け）
```

**あなたは新しいプロファイルを1つ追加します。**既存のものは消さないでください。
比較したり、戻したりできなくなります。

---

## ■ 書き換えるファイルは4種類だけ

| ファイル | 何が入っているか | 難易度 |
|---|---|---|
| `config.yaml` | キャラの設定・投稿の指示・CTA・商品リンク | ★★☆ |
| `rules_〇〇/` （新規作成） | 投稿の型・NGルール・勝ちパターン | ★☆☆ |
| `funnel/` | LINE の台本・商品情報・販売の原則 | ★☆☆ |
| `src/kantei.py` | 鑑定書の章立て（顧客ごとに書き換える） | ★★★ |

**プログラム本体（`src/` の他のファイル）は触りません。**触らなくても全部カスタマイズできます。

---

## ■ 手順1｜ルールのフォルダを作る

`rules_tsubaki/` をコピーして、`rules_〇〇/`（〇〇はあなたのキャラ名）にリネームします。

中身は7ファイルです。

| ファイル | 中身 | 書き換え |
|---|---|---|
| `01_persona.md` | キャラと読者の設定 | **必須** |
| `02_templates.md` | 投稿の型（13種類） | 必須 |
| `03_winning_elements.md` | バズの仕組み・CTAの基本 | 一部 |
| `04_avoid.md` | **禁止事項・安全ルール** | **必須（最重要）** |
| `05_learned.md` | 実データからの学習（自動更新） | 中身を空にする |
| `06_customer_voice.md` | 相談者の生の言葉（自動更新） | 中身を空にする |
| `07_buzz_swipe.md` | バズ投稿の参考集 | 任意 |

### 01_persona.md の書き換え

02 で決めたキャラの内容に置き換えます。表の形式はそのまま使ってください。

- 発信者のプロフィール（名前・肩書き・性格・口調・信念・決め台詞）
- 読者のプロフィール（属性・悩み・深層心理・お金の使い方）
- 反応する言葉／嫌う言葉

### 04_avoid.md の書き換え（ここは慎重に）

**「コンプライアンス」の項目は、テーマに合わせて書き換えつつ、絶対に緩めないでください。**

必ず残すもの：
- 結果・効果を保証する断定をしない
- 相手を不幸だと決めつけて過度に不安を煽らない
- 病気・健康・金運の断定をしない
- 実在の人物や嘘の体験談を捏造しない
- 高額商材をいきなり売り込まない

テーマ固有で足すもの：
- あなたの占術の専門用語を本文に出さない（例：宿曜 → あなたが使う体系の名前）

### 05_learned.md と 06_customer_voice.md

**中身を消して、見出しだけ残してください。**
これは実データから自動生成されるファイルです。前任者のデータが残っていると、
あなたのアカウントに合わない知見で投稿が作られます。

```markdown
# 学習で得た必勝要素（自動更新 / 未実行）

※ このファイルは `learn` コマンドが実データから自動生成・上書きします。
（まだデータがないため空です。運用開始後に自動で埋まります）
```

## ■ 手順2｜config.yaml にプロファイルを追加する

`profiles:` の下に、新しいブロックを追加します。
**`tsubaki:` のブロックを丸ごとコピーして、名前を変えて中身を書き換える**のが確実です。

### 書き換える項目

| 項目 | 中身 | 例 |
|---|---|---|
| `rules_dir` | 手順1で作ったフォルダ名 | `rules_〇〇` |
| `lead_keywords` | 相談の手挙げと判定する言葉 | テーマに合わせて |
| `offer` | 無料オファーの一文 | 02の決めた内容 |
| `line_url` | LINE公式アカウントのURL | |
| `web_diag_url` | 診断ページのURL | STEP 9で発行されたもの |
| `owner_line_user_id` | あなたのLINE ID（通知先） | |
| `system_prompt` | **投稿を書く時の全ルール** | 最重要 |
| `judge_system` / `judge_goal` | 生成候補を採点する基準（`post` コマンドで使用） | |
| `reply_system` | コメント返信の書き方 | |
| `learn_system` | 学習の分析基準 | |
| `variation` | 毎回振る要素（下記） | 最重要 |

### variation の中身（投稿の多様性を作る部分）

```yaml
variation:
  split_ratio: 0.5          # 分割投稿にする割合
  industries:               # 相談者の状況（8個くらい）
    - 〇〇で悩んでいる
  topics:                   # 切り口・テーマ（10個くらい）
    - 〇〇の本当の理由
  tones:                    # 文体（5個くらい）
    - 毒舌でズバッと言い切る
  ctas:                     # 締め方（10個くらい）
    - 「〜」と一文で締める（申込・DM導線）
    - 「〜？コメントで教えて」と参加だけ促す（拡散狙い）
  force_cta_directive: >-   # 3本に1本、必ず入る申込CTA
    【必須・最優先】…
  type_weights:             # 型の出現比率
    型①〇〇型: 26
  closing_directive: >-     # 毎回入る締めの共通指示
    …
```

**`ctas` は必ず3系統を混ぜてください。**
1. 申込を取る型（DM受付）
2. 申込を取る型（診断ページ誘導）
3. **何も配らない参加誘発型（拡散狙い）** ← これを半分くらい

全部を申込にすると、投稿が広がらなくなります。

### 最後に active_profile を切り替える

```yaml
active_profile: あなたのプロファイル名
```

### 確認

```bash
python -m src.main post --dry-run
```

キャラが自分の設定どおりに喋っていれば成功です。

## ■ 手順3｜funnel/ の台本を書き換える

| ファイル | 中身 | 書き換え |
|---|---|---|
| `claude_project_tsubaki.md` | LINE返信を作る時の指示書 | **必須** |
| `line_step_7days.md` | LINE の台本一式（あいさつ・オファー・納品文） | **必須** |
| `claude_project_shindan.md` | 診断ツールの指示書 | 任意 |
| `note_okyakusama_voice.md` | お客様の声のまとめ方 | 任意 |
| `instagram_reels.md` | Instagram展開 | 任意 |

### 書き換える中身

- キャラの名前・口調
- **商品名・価格・販売リンク**（ここを間違えると事故になります）
- 納期の約束
- 販売の原則（これはそのまま引き継いでください）

### 引き継ぐべき販売の原則

以下は実データで検証済みの原則です。**変えないでください。**

- 売る場所は会話の中だけ。一斉オファーは13件送って0成約
- オファーは相手から「どうしたらいい？」が出た瞬間だけ
- 無料の範囲では処方箋（いつ・何を・どう動くか）を渡さない
- 反応がない人にオファーを送らない
- 月額は、鑑定書の感想が返ってきてからだけ案内する
- 未成年には案内しない

## ■ 手順4｜鑑定書の章立て（購入が入ってから）

`src/kantei.py` の `CHAPTERS` は、**購入者1人ごとに書き換えます。**
テンプレートではなく、その人専用の指示を書く場所です。

### 流れ

1. 購入者から詳しい情報をもらう
2. `kantei_out/input_〇〇.txt` に整理して保存
3. `src/kantei.py` の `CHAPTERS` を、その人の話に合わせて書き換える
4. 実行する

```bash
python -m src.main kantei --name 名前 --me 1990-01-01 --him 1988-05-05 \
  --details-file kantei_out/input_〇〇.txt
```

**この書き換えは Claude Code にやらせてください。**
「この人の情報で CHAPTERS を書き換えて」と言えば、話の内容に合わせて章の指示を組んでくれます。

### 性質メモの追加

`SHUKU_TRAITS` に、その人と相手の性質が登録されていないと精度が落ちます。
実行前に Claude Code に確認させてください。未登録なら追加します。

### 前の人の章立てを保存しておく

書き換える前に、必ずコピーを取ってください。あとで参考になります。

## ■ 専門用語の最終ガード（必ず引き継ぐ）

`src/diagnosis.py` の `strip_jargon()` が、**占いの専門用語が本文に漏れたときに日常語へ置き換える最後の砦**です。
生成する全経路（無料診断・LINE自動返信・オファー・会員相談・月額鑑定・有料鑑定書）がここを通ります。

あなたのテーマに合わせて、`JARGON` に「本文に出してはいけない語」を登録してください。
**プロンプトで禁止するだけでは漏れます。**実際に有料会員への返信に専門用語が出た事例があります。

**この処理を2箇所にコピーしないでください。**必ず1箇所に置いて、全部からそこを呼んでください。

---

## ■ 触ってはいけないもの

**スプレッドシートの列構成を変えないでください。**
`src/store_sheets.py` の `TABLES` と1文字でもズレると、その機能が**エラーも出さずに静かに止まります。**
2026-08-01に、`scheduled_posts` の列が1つズレて自動投稿が完全停止した実例があります。

列を増やしたい場合は、シートとコードの両方を同時に直してください。片方だけは絶対にNGです。

---

## ■ よくある失敗

| 失敗 | どうなるか | 防ぎ方 |
|---|---|---|
| `config.yaml` と `rules_〇〇/` の CTA ルールが食い違う | AI が矛盾した指示を受けて出力が壊れる | 両方を同時に直す |
| `05_learned.md` を前任者のまま使う | 合わない知見で投稿が作られる | 中身を空にする |
| 商品価格をコードと台本の片方だけ直す | 客に違う金額を伝えてしまう | 全ファイルを検索して直す |
| 専門用語が本文に出る | 読者が理解できず離脱する | `04_avoid.md` に禁止語を明記 |

### 価格を変えたときの確認コマンド

```bash
grep -rn "古い価格" src/ funnel/ config.yaml
```

ヒットがゼロになるまで直してください。
