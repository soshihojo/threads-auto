# 08｜引き継ぎメモリ（新しいClaude Codeに最初に読ませて保存させるもの）

このファイルは、元の運用で数ヶ月かけて学んだ「コードにもマニュアルにも書ききれない知恵」です。
新しい環境のClaude Codeに、**「これを全部読んで、あなたのメモリに保存して」**と指示してください。

---

## 1. 購入報告が来たときの手順（毎回これ）

店主が「（名前/番号/メールアドレス）が購入してくれた」と送ってきたら、それは全部同じ意味＝購入者が出た。

1. スプレッドシートの `line_chats` を検索して該当ユーザーの user_id を特定
   （同姓同名に注意。番号・メール・直近の会話内容の一致で本人確定してから進む）
2. その人の**全トーク履歴**と `line_users`（生年月日・bot状態）を読み返す
3. `line_users` の `bot` 列を **hold** にする（自動返信を止める。売った後にAIが雑談を続ける事故を防ぐ）
4. 履歴の文脈に合わせた**番号付きヒアリング文章**を作って、コードブロックで全文出す
   - 会話で本人が既に答えたことは聞き直さない
   - 定番の型：呼び名／出会いと経緯／核心の出来事／現在の連絡状態／相手の立場（既婚・恋人の確認から逃げない）／よかった場面／本人の仕事・相談相手／生まれた時間／どうなりたいか（逃げ道つき）

## 2. 鑑定書の納品はセットで

鑑定書PDFを作ったら、**ファイルパスを示すだけで終わらない**。納品時にLINEに貼る文章（納品文）も同時に、コードブロックで全文出す。店主はコピペするだけの状態が完成形。

## 3. 顧客向け文面にMarkdownを混ぜない

`**太字**` や `#` はLINEやThreadsではそのまま表示されて興ざめする。コードのガード（strip_markdown）はAI生成文にしか効かない。**手で書く文面は自分で気をつけるしかない。**

## 4. git push とLINE消失の関係（実際に起きた事故）

push のたびに Render が再起動し、**再起動中に届いたLINEメッセージは記録されず、返信も永遠に来ない**。
- 変更は**1コミットにまとめてから push**。会話が活発な時間帯に連発しない
- 「返信が止まってる」と報告が来たら、まず**直近のpush時刻との重なり**を疑う
- 復旧は「さっきのぶん届いてへんかったみたい、もう一回送って」を push_text で送る＋履歴にも記録
- 恒久対策（構築時に済ませる）：LINE Developersで**Webhook再送ON**、Renderで**Health Check Path=/**

## 5. スプレッドシートの構造と手貼りのルール（42回連投事故の教訓）

- シートは**2行目がヘッダー、3行目からデータ、B列開始**。行番号の計算を間違えると別の人のデータを壊す
- `scheduled_posts` に手で行を貼るときは、**id列を「既存の最大値＋1」で必ず一意に**する。
  id重複すると「配信済みマーク」が別の行に書かれ、同じ投稿が無限に配信される（実際に42回配信された）
- 現在は `was_posted_before`（同一本文の再配信ガード）が入っているので暴走はしないが、idルールは守る
- config.yaml の `safety`（daily_post_cap等）は**コードから参照されておらず機能していない**。投稿本数は人間が管理

## 6. 販売の鉄則

- **オファーは、相手に「視てほしい／もっと知りたい」を言わせてから**。こちらから唐突に出さない。
  行動の二択（「このまま自分の勘で動くか。それともちゃんと視てから動くか」）で聞くと、
  実測で申込率が約3倍違った（19.2% vs 6.8%）
- **未成年には売らない**。例外なし（特商法・未成年者取消権）。無料範囲の上限に達したら黙って停止
- 決済ページの**住所入力は購入を落とす**。住所を取らない商品設定にする
- 価格は実測で決める。元の運用では 4,980円で0件 → 3,980円（通常9,980円の60%OFF表記）に変更
- CTAは**一動作だけ**。ただし「どの一動作か」は下の9番に書いた通り、実測で決着がついとる
- 無料会話の上限は7通。上限後は売り込みではなく静かに締める

## 7. 実測の基準値（元の運用のベースライン。新環境の比較用）

- 診断ページ：診断実施→LINEボタンクリック率 54%（押した人の82%は登録まで完走する。
  つまりボタンを押させるまでが勝負で、押した後の導線は壊れてへん）
- Threads投稿1本あたりのリード獲得 中央値3人
- 有料オファーの購入転換率：10%超なら価格維持、5%を切ったら値下げ検討
- 数字が取れるまで（30〜40オファー）は価格をいじらない
- オファー前に相手が「当たってる」系の言葉を出した人の購入率14%、出てへん人8%（1.75倍）
- オファー前の本人の発言数と購入率は逆U字。7〜11通が山（17〜20%）で、
  3〜6通は0〜8%、12通を超えると9%に落ちる。**深いほど良いは誤り**
- **オファー後に無言のまま終わった人からの購入はゼロ**（182人中0件）。
  買った人は全員、オファーの後に何か一言でも返しとる（返事があった人の購入率20%）

## 9. 投稿の締めは「彼の生まれ月をコメントに置いてって」一択（2026-08-14に確定）

313本・リード521件を締めの型ごとに突き合わせたら、勝負がついた。

| 締めの型 | 本数 | 獲得リード |
|---|---|---|
| 生まれ月をコメント | 67 | **513（全体の98.5%）** |
| DM誘導 | 61 | 5 |
| その他のコメント（🌙だけ等） | 36 | 2 |
| 固定投稿・プロフ誘導 | 80 | **1** |
| CTAなし | 69 | 0 |

- DM誘導と固定投稿誘導で**141本＝全体の45%を使うて、獲得は6件**やった。
  7月頭にDMが効いた記憶があったが、その後の61本が否定した。
  **過去の成功体験やのうて、直近の実数で判断する**
- バズと集客は対立せん。伸びた投稿でリードも取れとるのは全部この型（42,019v→55件、8,263v→45件）。
  逆に5,519v・5,339vの固定誘導回はリード0。**views が出ても、締めが場を移す形なら一件も落ちん**
- 「🌙置いてって」だけの抽象CTAも死ぬ。置くもんが「生まれ月」と明示されてへんと、
  読者は何を書いたらええか分からん
- **診断への誘導は、コメントに付いた返信の中で1対1でやる**。投稿本文からは場を移させん。
  投稿で拡散を取り、返信で刈り取る二段構え。これが「締め一択」が成立する理由や
- 投稿生成の指示文の完成形は `funnel/post_prompt.md` にある。**そのまま貼れば同じ品質が出る**

- **寄せる**：7時(595) / 22時(458) / 2時(411) / 15時(404) / 23時(403) / 20時(399) / 1時(345) / 11時(319)
- **捨てる**：19時(80) / 3時(169) / 16時(177) / 9時(179) / 13時(194)

## 11. 巡回が静かに止まる四つの穴（2026-08-14に全部塞いだ）

コメントが3時間放置された事故の原因は、一つやのうて四つ重なっとった。
新しい環境でも同じ構造なら、同じ穴が空く。

1. **処理の順番**：投稿を新しい順に見て上限で打ち切る作りやと、
   伸びとる最新投稿がコメント枠を食い潰して、**古い投稿のコメントは永久に拾われん**。
   → 全投稿から未処理を集めて、**コメントの時刻が古い順**に処理する
2. **巡回の時間帯**：cronが日中だけやと深夜のコメントを落とす。**24時間回す**
3. **APIの一時的な過負荷**：529が返った回が丸ごと死ぬ。**間を空けた再試行**を入れる
   （再試行するんは過負荷・レート制限だけ。入力の間違いは再試行しても同じ失敗を繰り返す）
4. **一人の失敗の波及**：先に「見た」と記録してから生成する作りやと、
   生成が落ちた人は**二度と拾われんまま消える**。失敗したら印を外して次の回でやり直させる

## 12. 手で送ったメッセージは履歴に残らん（見落としやすい）

`push_long_text` は送信するだけで、`line_chats` に記録せん。実害が三つある。

- ダッシュボードに出ん
- ボットが「まだオファーを出してへん」と誤解して**二重にオファーを出す**
- 「誰にいつ何を送ったか」の分析が実態とずれる

手で送る時は、**送信と同時に `add_line_chat` で履歴に残し、`bot=hold` にする**。

## 13. 日付を売る商品を出す前に、自動検査を入れる（`src/lint.py`）

暦や時期を売り始めると、**外れが記録される**商品になる。出す前に機械で三つ検査する。

- **予言文法**：「彼から連絡が来る日」を禁止し「あんたが動く日」に強制する。
  彼の行動を予言したら外れる。相談者の行動を指定したら、動いた事実が成果になって外れようがない。
  同じ情報を売っとるのに、片方だけが崩れる
- **日付の整合**：過ぎた日・期間外・存在せん日付（2月30日など）。
  ただし鑑定書の本文には「7月2日に別れた」みたいな過去の話が出るので、
  **これからの行動を指しとる文の日付だけ**を検査する（全部弾いたら一冊も出せん）
- **焼き直し**：前に渡した鑑定書との一致率。上位商品を買う人は下位を読んどるので、
  同じ話が出た瞬間に「これ前に読んだ」になる

★**公開面（Webの結果画面など）に出す文は、生成させずに手書きの表を引く**こと。
生成物の漏れ検査は生成系にしか掛かってへん。8/3に有料の納品物へモデル名が漏れた事故がある。
あれを全世界が見る画面で再演したら、その時点で終いや。

## 8. 仕事の流儀

- **施策は実測で検証してから広げる**。「良さそう」で終わらせず、before/afterの数字を取る
- 生成文が顧客に出る前のガード（占術用語・AI臭・英語混入の除去）はコードにあるが、
  **新しい混入パターンを見つけたら都度ガードに追加**する文化を続けること
- 事故が起きたら：止める → 原因特定 → その原因が二度と起きない構造をコードに入れる → 記録に残す
