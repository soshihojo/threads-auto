# 07｜二人体制での構築（開発はこっち、名義はあなた）

このファイルは、**システムを作る人（以下「開発側」）と、運用する本人（以下「あなた」）が別人**のときの分担表です。
考え方はシンプルで、

- **プログラムを書く・直す作業 → 全部開発側がやる**（あなたはコードを一切触らない）
- **アカウントを作る・キーを発行する・ボタンを押す → あなたがやる**（本人名義・電話番号認証・カード登録が要るので、本人にしかできない）

あなたの作業は「アカウントを作って、発行された文字列を指定の場所に貼る」だけに圧縮してあります。

> **あなたのパソコンに開発環境（Python・Git など）を入れる必要はありません。**
> Webアプリ（診断ページ・LINEボット・管理画面）の開発・修正・公開は全部開発側が遠隔でやります。
> あなたに必要なのはブラウザとスマホだけです。`03_構築手順.md` の STEP 1（Python の準備）は二人体制では不要です。

---

## ■ お金の仕組み（最初に理解しておくこと）

「Claude」と名の付くものが2つ出てきますが、**財布が別**です。

| 何 | 何に使う | 誰の財布 |
|---|---|---|
| **Claude Code**（開発ツール） | コードを書く・直す・投稿や鑑定書を作る | **開発側**のアカウントで作業する限り、開発側の消費 |
| **Anthropic APIキー**（`sk-ant-...`） | 稼働中のボットがLINE返信を自動生成するのに使う | **キーの持ち主**に課金。→ あなた自身で取得する（月数百〜数千円） |

つまり「作る費用」は開発側、「回す費用」はあなた。
サーバー（Render）・管理画面（Streamlit）・自動実行（GitHub Actions）・データ置き場（Googleスプレッドシート）は**全部無料枠**で動きます。有料はAPIキーとLINEの従量（ほぼ枠内）と決済手数料だけです。

> APIキーを開発側のものと共用にはしません。請求が混ざる・事故時に止めにくい・引き渡しが面倒、の三重苦になるためです。

## ■ 全体の流れ（フェーズ順）

```
Phase 0  あなた：GitHubアカウントを作って開発側を招待   …15分 ← ★これだけ最初に
Phase 1  二人 ：キャラ・商品を決める（02のワークシート）  …会話ベース
Phase 2  開発側：コード一式を「こはく」名義に作り直す      …あなたの作業ゼロ
Phase 3  あなた：各種アカウント作成とキー取得           …合計3〜4時間（数日に分けてOK）
Phase 4  二人 ：キーを設定画面に貼って接続テスト        …1時間
Phase 5  開発側：投稿ストックを仕込んで運用開始
```

## ■ Phase 0｜あなた：GitHubアカウント（最初にこれだけ）

GitHubは「プログラムの置き場」です。ここにあなた名義の置き場を作って開発側を招待すると、
**以後の実装・修正・改善は全部開発側が遠隔でできる**ようになります。

1. https://github.com を開く →「Sign up」→ メールアドレス・パスワード・ユーザー名を決めて登録（無料プランでOK）
2. 登録後、右上の「＋」→「**New repository**」
   - Repository name：`threads-auto`
   - **Private** を必ず選ぶ（Publicにすると中身が世界に公開されます）
   - 他は触らず「Create repository」
3. できたページ上部の「**Settings**」タブ →左メニュー「**Collaborators**」→「**Add people**」
   → 開発側のGitHubユーザー名を入力して招待 → 開発側が承認したら完了

これで Phase 2 は全部開発側の仕事になります。あなたは Phase 3 へ。

## ■ Phase 2｜開発側の作業（参考：あなたは読むだけでOK)

- リポジトリ複製、椿固有の文言・URL・商品情報の全除去
- 「椿→こはく」への置換実装：`rules_kohaku`（口調・NG集）／`src/web_diag.py`（診断ページの表記）／`config.yaml`／`funnel/`（LINEステップ・オファー文）／特商法ページ。設計・価格・文面の型は実証済みのものを流用
- 事故対策は移植済みの状態で渡す（同一本文の再配信ガード、購入サイン検知、未成年ガード等）
- あなたのPC用の設定テンプレ（`.env`、Render/Streamlitに貼るだけのファイル）を用意
- あなたのClaude Code用の引き継ぎ（後述）

> **あなたのリポジトリに入れないもの（開発側が責任を持って除外します）**：
> 元の運用の秘密鍵・トークン類、顧客の会話データ・鑑定書、実在のお客様の声。
> 渡すのは「仕組み」だけで、**git履歴も引き継がず新規リポジトリとして push** します
> （履歴に過去の顧客情報が残るのを防ぐため）。

## ■ Phase 3｜あなた：アカウント作成とキー取得（本人にしかできない作業）

**1日で全部やらないでください。**3-1〜3-3で1日、3-4〜3-6で1日、が目安です。
発行された「キー」「トークン」と呼ばれる文字列は、メモアプリに**名前を付けて**控えてください
（あとでどれがどれか分からなくなるのが一番の時間泥棒です）。

### 3-1. スマホ：Threadsアカウント（30分）

1. スマホに **Instagram** アプリを入れて、新規アカウントを作成（このビジネス専用。個人アカウントと分ける）
2. **Threads** アプリを入れて、そのInstagramアカウントでログイン → Threadsアカウントが自動でできる
3. Threadsアプリ内：設定 → アカウント → **プロアカウントに切り替え**
4. プロフィール文と画像は仮でOK（正式版は開発側が文面を作る）

### 3-2. パソコン：Meta開発者登録とThreads API（60分・一番の難所）

英語画面で分かりにくいところです。**詰まったらスクショを開発側に送ってください。**
細かい手順は `README.md` の「セットアップ 1〜2」にあります。要点：

1. https://developers.facebook.com/ で開発者登録（Facebookアカウントが要ります。なければ作る）
2. マイアプリ → アプリを作成 → ユースケースで「**Threads API**」を選択
3. 権限を有効化：`threads_basic` / `threads_content_publish` / `threads_manage_replies` / `threads_read_replies` / `threads_manage_insights` / **`threads_delete`**（←投稿の削除。最初に入れておくと事故時に助かります）
4. 「Threads testers」に自分のThreadsアカウントを追加 → Threadsアプリ側で招待を承認
5. トークンを発行 → **控える**（この短期トークンを開発側に渡せば、長期トークンへの交換は開発側がやります）

### 3-3. パソコン：Googleスプレッドシート（30分）

データ（会話ログ・予約投稿・顧客リスト）の置き場です。手順は `DEPLOY.md` の STEP 1。要点：

1. Googleアカウント（ビジネス専用に新規作成を推奨）
2. https://console.cloud.google.com/ で「サービスアカウント」を作り、**JSONの鍵ファイル**をダウンロード
3. スプレッドシートを1枚新規作成 → 「共有」でサービスアカウントのメールを**編集者**追加
4. シートURLの `/d/` と `/edit` の間の文字列（KEY）を控える

> ここで詰まったら無理しなくてOK。開発側のGoogle Cloudでサービスアカウントを発行して渡す逃げ道があります（その場合あなたの作業はシート作成と共有だけ）。

### 3-4. パソコン：Anthropic APIキー（10分）

1. https://console.anthropic.com/ に登録
2. クレジットカードを登録して **$5〜10** チャージ
3. 「API Keys」→ Create Key → `sk-ant-...` を控える
4. **このキーは誰にも見せない**（開発側にも本来渡す必要はありません。貼る作業は自分の画面でやります）

### 3-5. スマホ＋パソコン：LINE公式アカウント（60分）

手順は `DEPLOY_LINE.md` の STEP 1。要点：

1. https://entry.line.biz/ からLINE公式アカウントを開設（個人のLINEでログイン → アカウント名はキャラ名）
2. https://manager.line.biz → 設定 → **Messaging API** → 利用を開始 → **Channel secret** を控える
3. https://developers.line.biz → 同チャネル → Messaging API設定 → **チャネルアクセストークン（長期）を発行** → 控える
4. LINE公式アカウント管理画面 → 応答設定：あいさつメッセージ**オン**／Webhook**オン**／応答メッセージ**オフ**
5. **重要（事故対策）**：LINE Developers → Messaging API設定 → **Webhookの再送を「オン」**にする
   （サーバー再起動の瞬間に届いたメッセージが消える事故を防ぎます。実際に起きた事故です）

### 3-6. パソコン：Render・Streamlit・UptimeRobot（各15分）

3つとも「GitHubでログイン」を選ぶだけで登録できます（Phase 0のアカウントを使う）。

- **Render**（ボット本体のサーバー・無料）… https://render.com → GitHubでSign up。設定は Phase 4 で開発側と一緒に
- **Streamlit Community Cloud**（管理画面・無料）… https://share.streamlit.io → GitHubでサインイン
- **UptimeRobot**（サーバーを寝かせない番人・無料）… https://uptimerobot.com → 登録だけ

### 3-7. パソコン：STORES（商品ページ・30分）

1. https://stores.jp でショップ開設（本人確認あり）
2. 商品「個別鑑定書」を登録。**デジタルコンテンツ（ダウンロード販売ではなく「その他」）扱いにして、購入時の住所入力を求めない設定**にする（住所入力は購入率を落とすことが実測で分かっています）
3. 特商法の表記：あなたの氏名等が必要（STORESには個人の住所・電話を非公開にできる設定があります。開設フローの案内に従ってください）
4. 商品ページのURLを開発側に渡す

## ■ Phase 4｜二人：つなぎ込み（あなたの画面で貼り付け、開発側が誘導）

開発側が「**どの画面のどの欄に、控えたどの文字列を貼るか**」の一覧表（貼るだけファイル）を用意します。
あなたがやるのはコピペと、以下のボタン操作だけです。

1. **Render**：New → Web Service → リポジトリ`threads-auto`選択 →
   Build Command `pip install -r requirements.txt` ／ Start Command `uvicorn line_app:app --host 0.0.0.0 --port $PORT` ／ Instance Type **Free**
   → Environment に一覧表どおり貼る → Settings → **Health Check Path に `/` を設定**（←事故対策。必須）
2. **LINE Developers**：Webhook URL に `https://＜RenderのURL＞/webhook` → 「検証」ボタン → Success を確認
3. **Streamlit**：New app → `app.py` を選択 → Advanced settings → Secrets に一覧表どおり貼る → Deploy
4. **GitHub**：リポジトリ Settings → Secrets and variables → Actions → 一覧表どおり登録
5. **UptimeRobot**：New Monitor → HTTP(s) → RenderのURL → 5分間隔
6. **LINE公式アカウント管理画面**：あいさつメッセージ（友だち追加直後に届く一通）を設定
   （文面は開発側が用意します。貼るのはあなた）。あわせて**ベーシックID（@で始まるID）を開発側に伝える**
   （診断ページ→LINEの自動連携に使います）
7. **Threads**：プロフィール文と固定投稿（診断ページへの入口）を設定（文面は開発側が用意。貼るのはあなた）
8. **テスト**：自分のLINEからキャラにメッセージ → 返事が来る／診断ページ（RenderのURL+`/shindan`）で生年月日を入れる → 結果が出る → 出た番号をLINEに送る → 診断の続きが届く

> **通知（Chatwork）は使わない構成です。**そのぶん、購入サインや危険サインで
> ボットが止まった相談者に気づくのが遅れないよう、**LINE公式アカウントの管理画面（チャット一覧）と
> スプレッドシートの `line_users` タブを1日数回チェックする**運用にしてください。
> `bot` 列が `hold` になっている人＝あなたの出番、の合図です。

## ■ Phase 5｜運用開始後の分担と、開発の引き渡し

最初の作り込みは開発側がやりますが、**継続的な改善はあなた自身（あなたのClaude Code）でやる**計画です。

- 立ち上げ期：投稿の量産・オファー文・不具合修正は開発側。日々の「購入対応（bot=holdにする）」「入金確認」「シートを見る」はあなた
- 引き渡しのタイミング：システムが安定して回り、あなたが運用に慣れたら

### 開発の引き渡し手順（3ステップ）

1. **あなたのPCに開発環境を作る**：ここで初めて `03_構築手順.md` の STEP 1（Python・Git・Claude Code のインストール）を実施し、
   自分のリポジトリを手元に取得（クローン）する。やり方はClaude Codeに「GitHubの自分のリポジトリをクローンしたい」と聞けば案内してくれます
2. **あなたのClaude Codeに引き継ぎを読ませる**：下の「引き継ぐもの」を順番に読ませ、
   `handoff/08_引き継ぎメモリ.md` は「読んでメモリに保存して」と指示する
3. **開発側の権限を外す**：GitHubのリポジトリ → Settings → Collaborators → 開発側の名前の横の「Remove」。
   これで以後、リポジトリを触れるのはあなただけになります
   （あわせて、開発側に渡していたトークン類があれば再発行して貼り直すと、より綺麗に切り離せます）

## ■ あなたのClaude Codeに引き継ぐもの（移行時）

リポジトリを手元にクローンすれば、必要な知識はほぼ全部ファイルとして入っています。
あなたのClaude Codeに最初に読ませるのは次の順：

1. `handoff/README.md` → 案内役として全部読ませる
2. `CLAUDE.md`（このリポジトリの案内書。作業前に読むべきルールファイルの場所が書いてある）
3. `handoff/05_運用マニュアル.md` と `06_実績と失敗の記録.md`（何が起き、何で失敗したかの記録。同じ穴に落ちないため）

さらに開発側が `handoff/08_引き継ぎメモリ.md` として、運用中に学んだ「文章ファイルには残らない知恵」
（購入報告が来たときの手順、スプレッドシート手貼りのルール、顧客向け文面の禁止事項、
デプロイとLINE消失の関係、実測データの基準値）をまとめて置きます。
あなたのClaude Codeに「これを読んでメモリに保存して」と言えば、以後は向こうでも同じ品質で続きができます。
