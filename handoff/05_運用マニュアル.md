## ■ 毎日やること

### 1. 投稿を仕込む（10分）

**投稿は Claude のプロジェクトで作り、スプレッドシートに直接書き込みます。**
管理画面には生成機能はありません（2026-08-01に削除しました。理由は下記）。

**手順**

1. Claude のプロジェクト（`funnel/claude_project_tsubaki_posts.md` の内容を設定したもの）で投稿を作る
2. 出てきた文章を**必ず読む**
3. スプレッドシートの `scheduled_posts` タブの一番下に行を足す

**書き込む列は4つだけです。**

| 列 | 項目 | 何を書くか |
|---|---|---|
| B | id | 既存の最大値＋1（重複させない） |
| C | text | 投稿本文（改行はセル内改行でOK） |
| D | scheduled_at | `2026-08-06T20:00:00` ← **この書式で固定** |
| E | status | `scheduled` ← これ以外だと投稿されない |

F列以降（media_id・error・created_at・posted_at）は**空のまま**にします。投稿後にシステムが自動で埋めます。

> **D列の書式に注意。**Google スプレッドシートが勝手に日付型へ変換すると、**永久に投稿されません。**
> 列の表示形式を「書式なしテキスト」にするか、先頭に `'` を付けて入力してください。
> 入力後に**左寄せ**になっていればテキストです。右寄せなら日付型に化けています。
> 一番安全なのは、**既にある行をコピーして時刻だけ書き換える**方法です。

**読まずに投稿しないでください。**AI は時々おかしなものを出します。

チェックする点：
- キャラの口調が崩れていないか
- 専門用語が漏れていないか
- 保証するような言い方をしていないか
- 「◯月」のような伏せ字が残っていないか
- 締めが1つの動作で終わっているか（条件を並べていないか）

15分ごとに巡回する仕組みが、時刻の来た行を自動で投稿します（最大15分の遅れが出ます）。

### 2. 手動対応待ちの人に返信する（10〜30分）

**⚠️ 通知は一切ありません。自分で LINE 公式アカウントのアプリを開いて確認してください。**
1日2〜3回は見る習慣をつけてください。ここを見落とすと、買う気になっている人を取りこぼします。

誰が待っているかは、スプレッドシートの `line_users` タブで `bot` 列が `hold` の人です。

**この状態になる理由は3つです。**
1. 相手が購入サインを出した（料金・どうしたらいい 等）→ AI がオファーを送って停止した
2. 危険な発言があった（死にたい 等）→ AI が定型で受け止めて停止した
3. 無料の返信が上限（10通）に達した

**1 と 3 は、あなたが会話を引き継いで売る場面です。**
**2 は、絶対に売らないでください。**寄り添って、専門の相談窓口を案内してください。

返信は LINE 公式アカウントのアプリから手で送ります。
文面に迷ったら、相手のメッセージをそのまま Claude Code に貼って、
`funnel/claude_project_〇〇.md` のルールで作らせてください。

対応が終わったら、スプレッドシートの `line_users` タブで `bot` 列を `on` に戻すと自動返信が再開します。

## ■ 購入が入ったときの流れ

```
① 購入報告（オーダー番号）が届く
      ↓
② ヒアリング文を送って、詳しい状況を聞く
      ↓
③ 返ってきた情報を kantei_out/input_〇〇.txt に整理
      ↓
④ src/kantei.py の CHAPTERS をその人用に書き換える
      ↓
⑤ 鑑定書を生成する
      ↓
⑥ 内容をチェックする
      ↓
⑦ 納品文と一緒に PDF を LINE で送る
      ↓
⑧ 感想が返ってきたら、月額会員を案内する
```

### ②のヒアリングが一番大事です

**買ってすぐ作り始めないでください。**足りない情報を先に埋めます。

必ず聞くこと：
- 出会いから今日までの**時系列**（何がどの順番で起きたか）
- 相手の言葉を**そのまま**（要約されると読めません）
- 今の連絡状態
- 相手の背景（仕事・家族・過去）
- **本人が一番知りたい一問**
- 譲れない線（やってはいけないこと）
- 生まれた時間（分かれば）

**「一番知りたい一問」は必ず聞いてください。**これを鑑定書の背骨にします。

### ⑥のチェック項目

```bash
# 禁止語が混ざっていないか
grep -o "専門用語1\|専門用語2" kantei_out/個別鑑定_〇〇.html
```

- 占術の専門用語が出ていないか（自動で置き換える処理は入っていますが、念のため目視でも確認）
- 「必ず〜できる」という保証がないか（否定文脈ならOK）
- Markdown記号（`**` など）が本文に残っていないか
- 相談者を責める書き方になっていないか

### ⑦の納品文

**月額会員の案内は入れないでください。**納品と同時に次を売ると、
鑑定書が「次を売るための前振り」に見えて、読む前に信用が削れます。

納品文に入れること：
- その人が一番知りたかった問いに、**どの章で答えたか**
- 次に読む章と、そこに何が入っているか
- 相談の中でその人が自分でやっていた**良い一手**への言及

### 月額会員に毎月の鑑定を届ける

```bash
python -m src.main tsukiyomi --member "登録名" --name "呼び名" \
  --worry-file kantei_out/worry_〇〇_2026-08.txt --month "2026年8月"
```

生成すると同時に、内容が自動で保存されます（次回以降の相談の返信が、この内容を踏まえます）。
PDFはダウンロードフォルダにも置かれるので、そのままLINEに添付できます。

> **`--name` は必ず指定してください。**
> 会員の登録名には管理用の連番が入っていることがあり（例「美-02(月初ミニ鑑定)」）、
> 指定しないとそれが**鑑定書の表紙にそのまま出ます。**
> **その人の個別鑑定書で使った呼び名と、必ず同じ名前にしてください。**
> 毎月違う名前で届くと、覚えられていないと感じさせてしまいます。

## ■ 毎週やること

### 反応を見る（15分）

管理画面で、投稿ごとの表示数・いいね・返信・リード数を確認します。

**見るべきは表示数ではありません。**リード（相談に来た人）の数です。
表示数とリード数は関係ありません。3,154表示でリード1、86表示でもリード1でした。

チェックする点：
- リードが出た投稿の**締め方**は何だったか
- リードがゼロだった投稿の締め方は何だったか

締め方が全てです。フックの良し悪しではありません。

### 学習ファイルを確認する

3日ごとに `rules_〇〇/05_learned.md` が自動更新されます。
中身を読んで、「そうか」と思ったら投稿作りに反映してください。

## ■ 困ったときの対処

| 症状 | 原因 | 対処 |
|---|---|---|
| 投稿されない | **scheduled_at が日付型に化けている** | セルが右寄せなら化けている。書式なしテキストに直す |
| 投稿されない | status が `scheduled` になっていない | E列を確認 |
| 投稿されない | **シートの列とコードの定義がズレた** | 下の「列がズレたとき」を参照 |
| 投稿されない | トークン切れ／Actions のエラー | GitHub の Actions タブでログを確認 |
| LINE が返信しない | Render が寝ている | UptimeRobot が動いているか確認 |
| 管理画面が真っ白 | Secrets の設定ミス | JSON の三連クォートを確認 |
| 鑑定書が生成できない | API キーの残高切れ | Anthropic のコンソールで確認 |
| データが読めない | スプレッドシートの共有漏れ | サービスアカウントに編集者権限があるか |

### 列がズレたとき（実際に起きた障害）

2026-08-01に、`scheduled_posts` タブの列がコードの定義と1つズレて、**自動投稿が完全に止まりました。**
コードが期待する列がシートに無く、日付を別の列として読んでいたためです。表面上はエラーも出ません。

**確認のしかた**

シートの2行目（B2から右）と、`src/store_sheets.py` の `TABLES["scheduled_posts"]` を見比べてください。
順番も名前も完全に一致していないといけません。

現在の正しい並びはこの8つです。

```
B=id  C=text  D=scheduled_at  E=status  F=media_id  G=error  H=created_at  I=posted_at
```

**列を勝手に増やしたり減らしたり、並べ替えたりしないでください。**この一致が崩れた瞬間、投稿が静かに止まります。

### コードを消したあとに必ずやること

使わない機能を削除したときは、**起動確認だけで安心しないでください。**
実際に以下を動かして、落ちないことを確かめてください。起動は通るのに実行時に落ちる、が一番怖い壊れ方です。

```bash
# 無料診断が生成できるか（ファネルの入口。ここが死ぬと全部止まる）
./.venv/bin/python -c "from src.diagnosis import generate_reading; \
  print(generate_reading('1990-01-01','1988-05-05','音信不通','〜2週間','',for_line=True)['reading'][:80])"

# 未定義の名前が残っていないか
./.venv/bin/python -m pyflakes app.py line_app.py src/*.py

# 全部読み込めるか
./.venv/bin/python -c "from src import main, line_bot, diagnosis, schedule, store, content, kantei, web_diag; from line_app import app; print('OK')"
```

### 全部止めたいとき

- LINE ボット … Render の環境変数 `LINE_BOT_ENABLED=0` にして再デプロイ
- 特定の人だけ … スプレッドシートの `line_users` タブで `bot` を `off`
- 自動投稿 … GitHub Actions のワークフローを無効化

## ■ やってはいけない運用

### 1. 反応がない人にオファーを送る

一斉配信は13件送って0成約でした。関係が壊れるだけです。

### 2. Threads の DM や返信を大量に送る

**過去にアカウントが停止（BAN）されました。**
だから診断ページを入口にして、Threads 側では返信も DM も最小限にする設計になっています。

DM で受け付ける場合も：
- 1人につき1通だけ
- 同じ文面を連投しない
- 間隔をあける
- やり取りは LINE に寄せる

### 3. 画像で情報をもらう

購入報告のスクリーンショットなどは、自動処理できず見落とします。
**「オーダー番号を数字で送って」と必ず案内してください。**

### 4. 客に「店主」の存在を明かす

相談者から見ると、キャラ本人と話しているつもりです。
「担当者が確認します」のような言い方はしないでください。世界観が壊れます。

### 5. 値引き交渉に応じる

一度応じると、その人にも他の人にも示しがつかなくなります。

## ■ 数字の見方

### 続けるか見直すかの判断

有料鑑定を**実際にすすめた人数**で判断します。

- 30人にすすめて3件以上 → 続ける
- 30人にすすめて2件以下 → 60人まで延長して様子を見る
- 60人にすすめて4件以下 → 売り方を根本から見直す

### 売上の伸ばし方の順番

1. **まず購入者と感想を作る**（信用の土台。ここが無いと何も売れない）
2. 次に月額会員に繋げる（継続収入）
3. 最後に集客の量を増やす

**順番を逆にしないでください。**信用がないまま集客を増やしても、相談だけ来て AI 代が出ていきます。
